Detailed Description

Walks the company tree and visits the teams of a given profession.

The iterator collects the matching teams when it is created and starts on the first one, so it can be used straight away; first() goes back to the start. Departments are searched through getChild(); a Team is never searched any further. The list is a snapshot, so if teams are removed from the tree later the iterator holds dangling pointers. It lets the system find a team for a work unit without knowing how departments are stored.

Design pattern
Iterator (ConcreteIterator) over the company composite. It does not derive from Iterator because it returns Team objects, not work nodes.
