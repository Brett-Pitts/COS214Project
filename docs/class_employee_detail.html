Detailed Description

Abstract decorator that adds a detail (profession or competency) to an employee.

Holds the component it wraps, takes ownership of it and deletes it in the destructor. The name, core, profession and competency queries, setMediator() and doWork() are passed on to the wrapped component, so concrete decorators only add their own part.

Design patterns
  • Decorator (Decorator).
  • Template Method: doWork() runs this decorator's prepare() and perform(), then the wrapped component's doWork(), then this decorator's finish(). The versions of prepare(), perform() and finish() in this class do nothing; concrete decorators override them.
See also
EmployeeProfession, EmployeeCompetency

◆ doWork()

void EmployeeDetail::doWork ( WorkUnit * workUnit)
virtual

Does the work in layers.

Runs this decorator's prepare() and perform(), then the wrapped component's doWork(), then this decorator's finish(). The steps of the outermost decorator therefore come first and last, and the core employee's steps (and the mediator notification) are in the middle. A null unit is ignored.

◆ wrap()

void EmployeeDetail::wrap ( EmployeeComponent * component)
virtual

Adds a component to the end of the decorator chain.

If this decorator wraps nothing yet, the component becomes the wrapped component. Otherwise the call is passed down to the wrapped component. A null pointer and the decorator itself are ignored. The mediator is not set on the new component.

Note
If the chain already ends in an Employee or Manager, Employee::wrap() deletes the component. Wrap the core last.
Parameters
componentThe component to add. Ownership passes to the chain.
